# Web 界面结构简化设计（方案 A：一主一副）

日期：2026-09-05
状态：已确认方向，待实施

## 背景与目标

当前 Web 主界面为三区布局（左侧任务栏 / 中间会话流 / 右侧计划与改动栏）+ 首页新建任务面板。用户反馈整体「不够简洁」，确认方向为**结构上做减法**，目标气质为「简洁优雅」，对标ux/ 目录下设计稿的深色 + 品牌绿语言不变。

原则：可观测性（计划、改动、消耗）是产品核心卖点，不删除信息，只改变信息的在场方式——从「常驻」变为「一眼可见、按需展开」。

## 1. 会话页：三区 → 一主一副

- 右侧 `SessionRail`（web/src/session-rail.tsx）不再常驻渲染；会话页变为「左栏 + 中间会话流」双栏。
- 会话头部下方新增**紧凑状态条**（约 36px 高）：`计划 2/4` · `改动 3 文件 +45 −23` · `¥0.12` · 会话状态。数据来自现有 props（latestTodos / fileChanges / selected），无新增数据通道。
  - 各分段仅在对应数据存在时渲染；全空则整条不渲染。
  - 状态条分段之间用细分隔线或间距区分，禁止卡片化、禁止描边堆叠。
- 点击状态条（或头部「详情」按钮）以**右侧覆盖抽屉**展开原右栏全部内容（计划详情 / 文件改动 / 消耗 / 会话信息）。抽屉直接复用现有 `SessionRail` 组件，容器从常驻 `<aside>` 改为 overlay；点遮罩或 ✕ 关闭，Esc 可关闭。
- 「Agent 未调用工具就宣布完成」与「已完成但 todo 未完成」两类警告**不进抽屉**，内联在会话流顶部显示——它们是需要用户立刻看到的异常信号。

## 2. 左侧栏：可折叠

- 品牌区加折叠按钮；折叠后为窄图标栏（Logo / 新建任务 / 搜索 / 设置 / 扩展），图标带 tooltip。
- 折叠状态写 `localStorage`（键如 `myagent.sidebarCollapsed`），跨会话记忆。
- 分组（需要你处理 / 进行中 / 最近任务）与行尾状态标记保持不变。
- 移动端维持现有抽屉行为，不改。

## 3. 首页新建任务：合并精简

保留：大标题 + 副标题 + 大输入框（字数统计、项目选择 chip、先规划开关、发送按钮）。

删除 / 收纳：

- 删除「试试这些示例」区块（`EXAMPLE_PROMPTS` 与 `home-examples`）。
- 删除独立的「任务选项」`<details>` 折叠条；其内容（无人值守 / 权限档 / 隔离执行）收进输入框左下角「⚙ 选项」弹层（Popover，点外部关闭）。
- 「打开其他项目」入口挪进项目选择下拉里（option「打开其他项目…」）。

modal 形态（会话内新建）结构不变，仅跟随删除示例区（modal 本就没有示例区）。

## 4. 移动端

原本右栏就是底部抽屉。改为与桌面一致的状态条 + 上拉抽屉，复用同一状态条组件，行为基本不变。

## 5. 视觉约束（简洁优雅）

- 不新增颜色；沿用现有深色 + 品牌绿 token。
- 状态条、抽屉、选项弹层遵循「无卡片套卡片」：背景分层最多两级（页面底 / 浮层底），用透明度与 1px 分隔线区分层级。
- 抽屉宽度与现右栏一致（约 320px），带 200ms 左右滑入过渡，尊重 `prefers-reduced-motion`。

## 6. 错误与边界

- 状态条数据全部来自已有 props，任一缺失即跳过该分段，不显示占位符。
- 抽屉打开期间会话事件持续到达：抽屉内容实时更新，不锁定滚动位置。
- 零工具完成警告内联展示的条件不变（status=done && kind=run && toolCallCount=0）。

## 7. 测试与验证

- 更新 `web/src/SessionApp.test.tsx`、`session-plan.test.tsx` 等依赖 `.session-rail` 常驻的用例；新增状态条渲染（各分段有无数据）与抽屉开合的组件测试。
- Playwright E2E 中依赖右栏常驻选择器的用例改为先开抽屉。
- 完成检查路由：`pnpm run typecheck` → `pnpm test`；随后按项目约定做浏览器 GUI 实测（复杂/生产级用例：新建任务 → 执行 → 计划确认 → 完成态 → 抽屉查看改动），验证通过 computed style 与交互行为而非仅截图。
- 验证通过后直接提交 main 并推送。

## 不做的事（YAGNI）

- 不改设置 / 扩展 / 记忆 / 定时 / 统计等独立页面。
- 不改会话流内卡片（工具卡、审批卡、计划确认卡）的信息结构。
- 不引入新的状态管理 / 组件库；沿用现有 React + 手写 CSS。
