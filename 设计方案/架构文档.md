# MyAgent — 架构文档

## 1. 总体架构

**单引擎双前端**：Agent Core 是唯一大脑，CLI 与 Web 都只是把 Core 的能力接口翻译成各自协议的薄壳。

**纪律**：外围功能只能通过 Core 的公开接口接入（事件订阅、上下文注入点、模型层接口），任何前端不得绕过 Core 实现业务逻辑。

## 2. 事件流（架构的中枢神经）

Core 不 print、不直接操作 UI，只发出结构化事件。双前端各自订阅渲染；token 统计、JSONL 持久化也是事件订阅者（外部 webhook 推送为后续扩展的订阅者）。

| 事件 | 载荷 | 主要消费方 |
|---|---|---|
| `text_delta` / `thinking_delta` | 模型流式文本 / 推理内容 | CLI/Web 渲染 |
| `tool_call` / `tool_result` | 工具名、参数、结果摘要、diff | 渲染 + 持久化 |
| `todo_update` | 全量清单快照 | 进度面板 + 持久化 |
| `ask_permission` | 工具、命令、风险翻译、diff 预览、Agent 目的 | 审批 UI（看完再批；支持"拒绝并留言"） |
| `permission_denied` | 被拒工具与原因 | 回灌模型 + UI |
| `task_start` / `task_event` / `task_end` | 子代理过程，含成本归因 | 子任务卡片 |
| `run_started` / `run_finished` | 无人值守任务生命周期 | 统计面板 / 收尾总结 |
| `context_compacted` | 摘要、压缩比例、keepFromSeq | 提示 + 持久化 |
| `cost_update` | 本轮 token（in/out/缓存命中）、会话累计 | 对话流小字 + 持久化 |
| `wrapup_warning` | 优雅终止阶段（可配，默认 30/10/2 分钟） | 监控台提示 + 持久化 |
| `branch_summarized` / `label` | 分支摘要 / 书签 | 分支树 / 书签栏 |
| `session_info` | 会话元信息（标题等） | 索引重建（index.json 已废除） |
| `notify` | 完成/出错/审批超时 | 页面提示 + webhook/桌面通知订阅者 |
| `done` / `need_user` | 任务完成 / 需要用户决策 | 循环终态 → 前端等待输入 |

## 3. 会话与数据布局

```
<repo>/.myagent/                   # 仓库内（可进 git，团队共享）
├── config.jsonc                   # 项目共享配置
├── local.jsonc                    # 个人本地配置（gitignore）："本项目永久允许"规则等
└── memory/
    ├── conventions.md             # 命令约定、工具链
    ├── pitfalls.md                # 踩坑记录（带日期）
    └── decisions.md               # 架构决策（带原因）
（AGENTS.md 位于仓库根目录，随仓库共享）

~/.myagent/                        # 家目录（机器本地状态，不进仓库）
├── config.jsonc                   # 全局配置（含 trustedProjects 信任项目列表）
├── MEMORY.md                      # 全局用户偏好记忆
└── projects/<项目路径编码>/
    ├── scheduled.jsonl            # 定时任务注册（--at/--every，服务端轮询触发）
    └── sessions/
        ├── <session-id>.jsonl       # 会话事件流（追加写）
        └── <session-id>.trace.jsonl # 工程 trace（全量 req/res，排查用）
```

- **JSONL 每行一个事件**，追加写防崩，顺序重放可恢复任意会话（会话标题经 `session_info` 事件重建，不再依赖索引文件）。
- **压缩事件也是存储的一部分**：resume 时遇到 `context_compacted`，跳过其之前的原始消息，从摘要重建。
- **AGENTS.md**（项目根目录）每次会话自动注入系统提示，作为项目级持久指令。

## 4. 核心运行时结构

### 4.1 主循环（AgentLoop）

```
loop:
  1. 组装上下文 = 系统提示 + 记忆注入 + repo map + 历史(经软遗忘) + todo 快照
  2. 检查任务盒约束（时间/预算），临近触发则注入终止警告
  3. 流式调用模型（经 ModelRouter 选角色模型；turn 级指数退避重试）
  4. 分流模型输出：
     - 文本        → text_delta 事件
     - 工具调用    → PermissionEngine 判定 → ToolExecutor 执行（批次可并行，
                    含审批需求自动退串行）→ 结果回灌，回到 1
     - 宣布完成/提问 → done 软拦截（todo 有未完成项时注入提示继续，≤2 次）
                     → 发出终态事件，退出循环等待用户
  5. 每轮检查 token 预算，触发软遗忘/硬压缩
  6. 轮间检查用户新输入（软打断）与 Esc 信号（硬打断）
```

未声明 `--check` 时，退出权仍主要在模型手里：它宣布完成、或需要人做决定时循环停止。声明 `--check` 后，系统会在模型完成后执行验收命令，失败则携证据打回修复（最多 2 轮）；检查通过且产生任务期文件改动时自动运行独立 Completion Review。普通任务仍可由 `behavior.completionReview` 或 `/review` 触发审查。批次副作用（事件+回灌+trace）由 `tool-batch.ts` 的 `executeTool`/`emitToolResult`/`emitDeniedTool` 原语收敛；缓存浪费度量（`computeMissedTokens` 等）独立在 `cache-stats.ts`。

### 4.2 子代理（TaskRunner）

同一个 AgentLoop 的嵌套实例，跑完即焚：

- **上下文**：空白 + 主 Agent 自写的完整 prompt（不继承主对话历史）
- **工具**：默认只读（Read/Grep/Glob/只读 Bash），写权限需显式开启
- **模型**：默认走 `explore` 角色（便宜模型）
- **权限**：继承父级档位；审批请求冒泡到主会话 UI
- **限制**：最多嵌套 2 层，并发上限 4，默认最多 40 轮（超限强制收尾），可设单任务 token 预算
- **回流**：仅最终结论（结论/证据/未确认三段式）返回主上下文；过程走 `task_*` 事件可观测

### 4.3 权限引擎（PermissionEngine）

判定顺序（任一命中即出结果）：

```
deny 规则命中              → 直接拒绝（任何档位不豁免）
档位 = strict 且为写/Bash  → 发 ask_permission（忽略 allow 记忆）
ask 规则命中               → 发 ask_permission
allow 规则命中             → 放行
档位 = trust               → 放行
档位 = normal 且为只读/Edit/MultiEdit → 放行
档位 = strict 且为只读     → 放行
其余                       → 发 ask_permission，等待批准
```

- 三档（strict / normal / trust）为会话级状态，运行中可切换；`/run --permission` 为**任务期临时档位**，任务结束回落原档位
- 规则按命令模式 + 文件路径匹配（如 `Bash(npm test *)`、`Edit(~/.ssh/**)`）；无人值守任务的 `--bounds` 负面清单编译为会话级临时 deny 规则
- **只读白名单防写绕过**：`segmentWritesFile` 引号感知识别写重定向（`>`/`>>`/`>|`/`N>file`，排除 `2>&1` 与 `/dev/null`）与 `tee`——`cat x > out` 不因 `Bash(cat*)` 白名单放行，只读子代理同受约束
- 批准记忆四级：仅一次 / 本次会话 / 本项目 / 全局（后两级写入分层配置，热生效）
- 无人值守超时自动拒绝（fail-closed）；`--approve-timeout` / `--auto-allow` 任务级覆盖
- deny 是硬边界，不提供“仍然执行”入口；用户要改变行为必须先修改或删除规则

### 4.4 上下文管理（ContextManager）

| 层级 | 机制 | 触发 |
|---|---|---|
| 软遗忘 | 老工具结果替换为占位符（含恢复指引），保留最近 N 轮 | 每轮检查 |
| 硬压缩 | 全对话 → 结构化摘要（目标/已改/关键文件/todo/偏好）+ 近期原文 | token 阈值（自动）或手动 |
| 子代理隔离 | 探索任务派生独立上下文，只回流结论 | 模型自主决策 |
| 缓存前缀工程 | system 只放低频稳定内容；记忆类静态段会话内只构建一次（写记忆不刷新当前会话）；todo 移出 system 作为独立消息注入 messages 尾部 | 始终 |

缓存前缀工程的原理：prompt 缓存要求两次请求前缀字节级一致，任何高频变化内容进入 system 都会破坏其后整个 messages 历史的缓存。实测命中率 4% → 66.4%。

### 4.5 模型路由（ModelRouter）

| 角色 | 用途 | 配置示例 |
|---|---|---|
| `main` | 主循环推理 | claude-sonnet |
| `cheap` | 硬压缩摘要、会话标题 | claude-haiku / deepseek |
| `explore` | 子代理探索 | deepseek / kimi |

- **fallback 链**：每角色可配候选列表，选中模型不可用/失败时自动顺延；供应商缺失降级为即抛客户端（`model-factory.ts` 的 `buildRoleClientChain`）
- **thinking**：Anthropic extended thinking / OpenAI reasoning，会话内保留推理，模型不支持自动降级重试
- **消息转换层**（`transform-messages.ts`）：请求前 toolCallId 归一化、相邻 assistant 合并（半截回合）、孤儿 toolCall 补结果、空 assistant 丢弃——切换供应商不丢质量
- **流式 fallback**：首候选流式中途失败自动顺延下一候选重放
- **缓存隔离**：摘要/分支摘要等一次性辅助请求传 `cacheRetention: "none"`，不污染主会话缓存前缀
- 路由规则可配置；每次调用记录 token（in/out/缓存命中）→ `cost_update` 事件 → 对话流小字 + 持久化

## 5. Web 服务形态

- 本机 Node 进程，默认绑 `127.0.0.1`；配置显式开启后才监听外部（配访问密码，供手机审批场景）
- **REST** 承载能力接口（会话列表、配置读写、记忆浏览）；**SSE** 推送事件流（对话、进度、审批请求）
- 前端从同一份 Config Schema 自动生成设置界面（含 string[] 行编辑器，如信任项目）；响应式布局适配手机
- 页面：监控台 / 会话详情（来源筛选、交付摘要、任务清单三态）/ 记忆面板（时间线审计）/ 定时任务面板 / 任务统计面板（收尾总结模态）/ 插件面板（加载清单、热重载、动态工具注册）/ 设置页
