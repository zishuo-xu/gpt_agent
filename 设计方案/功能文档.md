# MyAgent — 功能文档

> 面向使用者的功能说明：这个 Agent 怎么用。

## 1. 启动方式

shell 层只有两个入口，参数如下：

| 命令 | 作用 |
|---|---|
| `myagent` | 进入交互 CLI（任务的唯一入口） |
| `myagent --web` | 启动本地 Web 界面（默认 http://localhost:3000）；`--port <n>` 覆盖端口；`--daemon` 守护进程化（detach + 日志轮转，`--daemon-stop` 停止）；`--force` 跳过单实例写锁（仅崩溃残留确认后使用，多进程并发写会损坏事件流） |

`--version` / `-v` 打印版本号。

进入 CLI 后，直接打字就是聊天干活；所有操作通过内部命令完成（完整列表见 §2.3）。

## 2. CLI 交互

### 2.1 对话与干活

直接用自然语言下达指令。Agent 会自主探索代码库、编辑文件、运行命令，并根据错误反馈和验收证据在当前任务内重试。

- 复杂任务时自动维护 **todo 清单**，实时显示在界面侧栏：已完成 / 进行中 / 待办
- 编辑文件后展示 **diff 高亮**，改在哪一目了然
- 派生**子代理**探索代码时，主对话中显示可折叠卡片（任务名、工具调用次数、消耗 tokens），点开可看过程

### 2.2 打断

- **直接打字**：消息排队，Agent 当前这轮做完后响应（软打断）
- **Esc**：立即中止模型生成与当前工具（硬打断）。内置文件编辑保证原子性，不会留下半个文件；Bash 会终止整个进程组，但已经发生的外部副作用无法自动撤销，界面会明确提示

### 2.3 会话内命令

| 命令 | 作用 |
|---|---|
| `/run <任务> [--until 07:00] [--budget 5] [--permission trust] [--at 09:00] [--every 30] [--approve-timeout 30] [--auto-allow "Bash(pnpm*)"]` | 启动任务：无人值守迭代就加约束，一次性小任务什么都不加（干完自然停）；`--at`/`--every` 为定时规格（仅 Web 服务端生效，见 4.1）；`--approve-timeout`/`--auto-allow` 为任务级审批控制（见 4.1） |
| `/sessions` | 查看会话/任务列表 |
| `/switch <id>`（别名 `/resume`） | 切换/恢复会话 |
| `/permission <strict\|normal\|trust>` | 切换权限档 |
| `/compact` | 手动触发上下文压缩 |
| `/init` | 初始化项目：扫描后生成 AGENTS.md 草稿，你确认/编辑后保存（进入陌生项目默认零操作，不会自动扫描） |
| `/cost` | 查看本次会话消耗（token 为主） |
| `/config ...` | 查看/修改配置（与 Web 设置页同一套） |
| `/allow [once\|session\|project\|global]` | 批准当前审批并选择记忆范围 |
| `/deny [留言]` | 拒绝当前审批，可附纠正意见 |
| `/help` / `/exit` | 查看命令列表 / 退出 |
| `/steer <指令>` | 插队打断：当前工具完成后转向处理新指令 |
| `/model <供应商/模型>` | 热切换当前会话模型（`/model` 查看候选） |
| `/review` | 对最近一次完成运行独立审查（任务验收链，开发验证用） |
| `/trust` | 将当前目录标记为信任项目（见 3.3） |
| `/undo` | 撤销最近一次 Agent 编辑（文件已被后续修改时拒绝，不误撤用户手动改动） |
| `/tree` | 分支树总览 |
| `/branch <seq> [label]` | 从指定消息建立实验分支 |
| `/goto <branch>` | 切换到指定分支 |
| `/timeline` | 时间线视图 |
| `/label <name> <seq...>` / `/labels` / `/unlabel <name>` | 消息书签：打标 / 查看 / 移除 |

## 3. 权限与批准

### 3.1 三个档位

- **strict**：Edit / MultiEdit / Write / Bash 全部要你确认；已记住的 allow 规则在本档不生效——适合陌生项目
- **normal**（默认）：读操作与 Edit / MultiEdit 自动放行；Write 询问；Bash 仅安全白名单（跑测试、git status 等）自动放行，其余询问
- **trust**：除 deny 与显式 ask 规则外自动执行——适合无人值守

### 3.2 批准弹窗（看完再批）

- **改文件（Edit/Write）**：批准前先展示真实 diff（改动块 ±3 行，大改动折叠可展开）；新文件显示前 20 行预览
- **跑命令（Bash）**：卡片 = 命令原文 + 一行风险翻译（"将修改 package.json 与 lock 文件""⚠ 递归删除目录"）+ Agent 的目的
- **批量放行**：挂起审批 ≥2 时出现「全部允许（本次会话）」按钮，一次放行审批风暴
- **批准选项**：仅这一次 / 本次会话都允许 / 本项目永久允许 / 全局永久允许 / **拒绝并留言**（附一句纠正，Agent 立刻换方案）
- normal 档下 Edit 自动放行（有 EditJournal 与事后 diff 可查），审批弹得少但每次都值得细看
- **只读白名单防写绕过**：`cat x > out` 这类带写重定向的命令段不因 `Bash(cat*)` 只读白名单放行（`tee` 与引号感知解析），只读子代理同样受约束

规则随时可在 Web 设置页查看、增删。

规则优先级固定为 `deny > strict 档 > ask > allow > trust 档 > normal 默认策略`。deny 永远直接拒绝，不提供临时强制放行。

### 3.3 无人值守安全

- 审批请求超时（默认 5 分钟）无人响应 → 自动拒绝，Agent 换路继续或收尾
- 黑名单规则任何档位都不豁免
- **信任项目两段式**：`/trust` 把当前目录标记为信任项目（写入全局配置，Web 设置页可管理）；权限档为 trust 且目录未标记时 CLI 启动提示一次——显式信任声明，不改变权限档位语义

## 4. 无人值守模式

```bash
# 交互界面中输入：
/run 继续迭代 RAG 项目，优先完善检索评估 \
  --goal "pnpm test:eval 的 recall@5 ≥ 0.80" \
  --bounds "不改 src/api/ 目录，不动数据库 schema" \
  --until 07:00 --budget 5 --permission trust
# 任务在当前会话持续运行，终端保持开着即可
```

- **任务三要素**：`--goal` 描述目标，重复 `--check` 声明由系统执行的机器验收命令；`--bounds` 负面清单（路径类编译为 deny 规则并在启动前展示确认一次；语义类注入强提示约束）；时间/预算盒
- **时间盒**：到 07:00 自动收尾；**预算盒**：花费到 5 元自动收尾
- **优雅终止**：分阶段警告（阶段可配，默认剩余 30 分钟收窄范围 → 10 分钟进入收尾 → 2 分钟只输出总结）。优先把代码恢复到可编译状态；只能通过编辑日志撤销 Agent 自己且未被再次改动的编辑，无法安全恢复时保留现场并明确报告
- **模型容错**：遇限流/断网自动指数退避重试，可配备用模型降级；彻底失败时通知你并优雅收尾保留现场
- **权限档**：`--permission trust` 仅任务期生效，任务结束回落原档位
- **收尾三件套**：总结报告（含验证结果前后对比）+ todo 快照（明天接着干）+ 记忆写入
- **选任务原则**：只把"验收标准机器可判定"的任务放过夜（测试/lint 过没过）；需要人脑判断"好不好"的任务不适合无人值守
- **通知**：页面内为主——状态变化、标签页标题提示（如 `(1) 等待审批`）；外部推送已实现（见 4.2）：webhook（企业微信 / 飞书 / Bark / 通用 JSON）+ macOS 桌面通知，不配也能完整使用
- **远程监控**：浏览器打开 Web 界面（手机也行）看实时进度；审批请求出现在页面上，点一下放行；超时无人理会则自动拒绝换路继续

### 4.1 定时触发（Web 服务端）

- `/run ... --at 09:00`：每天 09:00 触发；`/run ... --every 30`：每 30 分钟触发一次（首个周期从注册时刻顺延）；两者可组合（如 `--at 09:00 --every 1440` = 每天 09:00）
- 注册入口：Web「定时任务」面板（按项目隔离）；`--at` 当天已过自动顺延到明天
- 到期由本机 Web 服务轮询（每 30s）启动会话，无需保持页面打开；周期任务按原定时刻重排不累积漂移；一次性任务触发后即从磁盘移除
- 持久化于项目 stateDir 的 `scheduled.jsonl`，服务重启后继续生效
- 调度任务与手工 `/run` 同一执行路径（权限档 / 硬边界 / 预算盒全部生效）；无人值守下审批超时自动拒绝（fail-closed）
- **任务级审批控制**：`--approve-timeout 30` 把任务期审批超时缩到 30 秒（缺省沿用会话级 5 分钟，任务结束恢复）；`--auto-allow "Bash(pnpm*),Read(*)"` 任务期自动放行指定规则（权限引擎仍强制 deny，结束随权限档回落，不并入会话记忆）
- **启动失败重试**：会话创建失败自动顺延 5 分钟重试，连续 3 次失败丢弃并在服务端日志告警（attempts 持久化，重启不重置）
- **每日花费上限**（`behavior.dailyBudgetCny`，0 = 关闭）：按项目当日累计费用超限时暂停触发并顺延——周期任务保相位重排到下一周期，一次性任务顺延 24 小时；恢复后自动继续
- **执行记录**：每次触发记录 `lastRunAt/lastRunStatus/lastRunSessionId`（启动成功 / 启动失败 / 预算顺延），面板展示"上次触发"并可从会话跳转

### 4.2 任务结果触达（通知）

- **webhook**（`notify.webhook`）：任务完成 / 失败 / 中断 / 出错 / 审批超时推送；`/run` 收尾推送含耗时、费用、输入 tokens；同一会话每小时最多 2 条防刷屏
- 格式自动适配：企业微信机器人（msgtype）、飞书机器人（msg_type）、Bark（title/body）、其他网关通用 JSON POST——**通用网关附带结构化字段**（status / sessionId / costCny / tokens / durationMs），机器人可做卡片；企微 / 飞书保持文本格式不变
- **macOS 桌面通知**（`notify.desktop`）：同等事件弹系统通知中心，无需浏览器常驻
- 推送失败静默忽略，不影响主流程

### 4.3 会话保留策略

- `behavior.sessionRetentionDays`（默认 30，0 = 关闭）：Web 服务启动时与每日清理超过该天数未更新的会话（事件流 + 书签 + 分支一并删除，记忆面板时间线自动消失——它是从会话事件实时推导的）
- 运行中 / 等待审批的会话跳过；清理数量在服务端日志留痕

## 5. Web 界面

### 5.1 监控台（首页）

所有会话的状态卡片：项目名、任务标题、运行状态、todo 进度条、累计花费、已运行时长。点卡片进入会话详情。

### 5.2 会话详情

- 左侧：完整对话流（文本、工具调用、diff 高亮、子代理卡片），顶部来源筛选（全部 / 推理 / 工具 / 子代理 / 系统）
- 右侧：todo 面板（三态标记 ✓/→/○，有任务清单自动展开）+ 消耗卡（token 口径）+ 会话信息；会话完成但存在未完成项或零工具调用时显示警告条
- **交付摘要**：会话完成且有写操作时，事件流底部展示改动文件列表与验证结果（纯事件流推导，零额外成本）
- **对话链路**：右侧面板按轮次列出所有用户提问（序号 + 摘要 + 时间），点击平滑定位到对应消息——长会话导航不再靠滚轮
- **Trace / 对比**：每个 Turn 用已有记录读出「看见 / 决定 / 做了」，并记下工作区指纹。对比页先判断能不能隔离（模型、Overlay、指纹）；隔离失败只展示工具序列事实，不下结论
- 底部：输入框（可发送消息或批准请求）

### 5.3 记忆面板

浏览 Agent 沉淀的记忆：项目约定（conventions）、踩坑记录（pitfalls）、架构决策（decisions）、全局偏好（preferences）。可直接编辑、删除；每次 Agent 自动写入都有记录（"它学到了什么"时间线）。

### 5.4 成本透明（轻量，非独立页面）

- 每轮对话末尾一行小字：`本轮 12.4k in / 1.8k out · 缓存命中 78% · 累计 89k`（token 为主，金额为括号小字）
- 会话卡片与侧栏显示累计消耗；`/cost` 命令随时查
- 完整数据记录在会话文件中，需要深度分析时可随时导出

### 5.5 设置页

- 模型配置采用供应商列表 + 详情双栏：支持启用/禁用、Anthropic Messages 与 OpenAI-compatible Chat Completions、自定义 Base URL 和 API Key
- 每个供应商可维护多个模型；每个模型有独立“测试连接”，通过一次最小真实调用验证认证、接口路径、模型名称并显示延迟
- 主模型 / 压缩模型 / 探索模型从已启用供应商的模型列表中分别选择
- 权限规则表（allow/ask/deny，增删改）
- 行为参数（压缩阈值、审批超时等）
- **信任项目**：`/trust` 标记的目录列表，文本域按行编辑（string[] schema 驱动）
- 服务器（监听地址、访问密码）；通知（webhook 地址 / 桌面通知开关）
- 全局 / 当前项目两个作用域切换

### 5.6 定时任务面板

- 按项目注册 / 删除定时 `/run`（`--at` / `--every` 语法同上）；列表展示干净命令、触发方式与下次执行时间
- 到期由服务端 ticker 启动会话，列表每 30s 自动刷新（触发后一次性任务消失）

### 5.7 任务统计面板

- 会话用量聚合：总量卡（会话数 / 完成 / 失败 / 中断 / 无人值守数 / 输入 tokens / 累计费用）+ 按天分桶柱状图（tokens 与费用双柱，纯 CSS 无图表库依赖）
- **按模型成本**：cost_update 事件携带模型来源（fallback 链透传 providerId/model），跨会话聚合"模型 × 供应商 × 费用 × tokens"维度表（费用占比条）——多供应商调优的直接依据；历史会话（修复前）无模型字段，从新会话开始积累
- 会话明细表：时间 / 标题 / 类型 / 状态 / tokens / 费用，按创建时间倒序；数据来自会话 summary（`totalInputTokens` / `totalCostCny` 等），不新增埋点
- **收尾总结**：无人值守会话行可点「查看」打开模态——run_finished 之前最后一段助手文本（总结报告）+ todo 快照 + 状态 / 时间范围 / 耗时 / 费用（`/api/sessions/:id/summary` 从事件流推导）

### 5.8 插件面板

- 加载清单 / 加载错误 / 调用统计可视化
- 「重新加载」按钮热重载（无需重启 server）；单插件启用 / 禁用（状态持久化到 `plugins.json`，重启保留）
- 插件热加载后主会话与子代理下一轮即对模型可见（动态工具注册）
- 插件工具与内置工具同权限审批与 UI 渲染（协议见 §9）

## 9. 插件与工具扩展

- **插件通道**：`.myagent/tools/*.ts`（项目级）或 `~/.myagent/tools/`（全局，项目覆盖）写一个 `definePluginTool` 即接入——注册、模型可见、执行分发、权限审批、UI 渲染全走通用通道
- **BrowserCheck**：无头浏览器页面检查（HTTP 状态 / 标题 / console 错误 / 渲染后文本）——搭完 UI 启动 dev/preview 后，模型可验证页面真实渲染（需 `npx playwright install chromium`）
- **WebSearch**：searxng 自托管（本机 Docker）→ tavily（可选云 API）→ HTML 引擎链（bing/ddg/baidu）兜底；深度模式默认自动抓取前 2 个结果页正文
- **WebFetch**：反爬增强的页面抓取（浏览器级请求头 / 失败重试 / 可选 cookie）
- **MCP 接入**：`plugins.json` 的 `mcpServers` 段配置后自动注册进插件通道（stdio 子进程 / 远端 HTTP 双传输）
- **超时护栏**：插件 run 默认 60s 限时，超时返回失败结果不卡死 agent 循环；可声明 `timeoutMs` 覆盖
- 完整协议与架构链路见 `docs/plugin-tools.md`

## 6. 记忆

- **项目记忆**：`AGENTS.md`（仓库根目录，随 git 共享；由 `/init` 生成草稿、你确认后生效）+ 仓库内 `.myagent/memory/` 下的 conventions / pitfalls / decisions（可随仓库共享）；会话、trace 等机器状态存在家目录，不进仓库
- **全局记忆**：`~/.myagent/MEMORY.md`（跨项目偏好）
- Agent 干活中学到稳定事实（如"本项目测试命令是 pytest -x""Chroma 连接要加超时"）会**自主写入记忆**，下次会话自动带上；**写入在本次会话内不立即注入**（为保持上下文前缀稳定以最大化缓存命中，新记忆下次会话生效）
- 跨项目联想：新会话会看到他项目记忆的标题索引，相关时 Agent 主动调取全文

### 6.1 记忆治理（轻治理三层防线）

1. **写入可见**：记忆面板的"它学到了什么"时间线，每次自动写入均可审计
2. **写入自律**：模型只写稳定事实（命令、约定、已验证的坑），推测性内容标"待验证"
3. **删除即治理**：面板一键删除，或对话中指出错误由 Agent 自己修正；不做写入审批制（避免成为新的打断源）。错记忆会在下次使用时被 Agent 自行发现并修正

## 7. 多模型

- 主循环、压缩摘要、子代理探索可分别配置不同模型
- 支持 Anthropic 与任意 OpenAI 兼容端点（DeepSeek / Kimi / GLM）
- 每次调用自动记录 token 与费用，对话末尾小字或 `/cost` 可查

## 8. 会话管理

- 所有会话自动持久化，崩溃不丢（最多丢最后一行）
- `/sessions` + `/switch` 或 Web 首页选择任意历史会话继续
- todo 状态随会话恢复，未完成的任务接着干
## 交付验收工作台

会话交付通过事件驱动投影区分任务结果、机器验收和 Review 状态，并展示完整成功文件清单、验收输出及隔离工作区变化。系统不会自动合并、commit、push 或删除；文件清单不是仓库 raw diff，避免暴露任务开始前的 dirty 内容。
