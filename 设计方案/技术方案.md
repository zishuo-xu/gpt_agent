# MyAgent — 技术方案文档

> 本文讲"怎么做"：技术选型、各模块的实现方案与关键协议。架构层面"是什么"见《架构文档》。

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 语言/运行时 | TypeScript + Node.js | 生态最接近 Claude Code 原生形态；前后端同构 |
| 模型 SDK | Anthropic SDK + 自研 OpenAI 兼容适配器 | 多供应商统一抽象 |
| CLI 渲染 | Ink（React 写终端 UI）或纯流式输出起步 | Claude Code 同为 React-based |
| Web 后端 | Hono（轻量，REST + SSE 顺手） | 无重型框架依赖 |
| Web 前端 | React + Vite | 监控台/记忆面板等富交互 |
| 存储 | JSONL 文件 + JSONC 配置 | 零依赖、防崩、可审计；不引入数据库 |
| 仓库解析 | tree-sitter（repo map 用） | 多语言签名提取 |

## 2. AgentLoop 实现方案

### 2.1 事件流基座

Core 内部用 `EventEmitter`（或 AsyncGenerator）发事件，定义统一类型：

```ts
type AgentEvent =
  | { type: 'text_delta'; text: string }
  | { type: 'tool_call'; id: string; tool: string; args: unknown }
  | { type: 'tool_result'; id: string; summary: string; diff?: string; truncated: boolean }
  | { type: 'todo_update'; todos: TodoItem[] }
  | { type: 'ask_permission'; id: string; tool: string; detail: string; risk: string }
  | { type: 'task_start' | 'task_event' | 'task_end'; taskId: string; ... }
  | { type: 'context_compacted'; ratio: number; summary: string; keepFromSeq: number }
  | { type: 'cost_update'; in: number; out: number; cacheHit: string; totalTokens: number; cost?: number }
  | { type: 'wrapup_warning'; stage: 't-30min' | 't-10min' | 't-2min' }
  | { type: 'notify'; level: 'info' | 'warn' | 'error'; message: string }
  | { type: 'done' } | { type: 'need_user'; question: string }
```

订阅者：CLI 渲染器、Web SSE 推送、SessionStore（落 JSONL）、通知 webhook、成本统计器。**新增外围能力 = 新增订阅者，不改 Core。**

### 2.2 主循环伪代码

```ts
async function* run(loop: AgentLoop): AsyncIterable<AgentEvent> {
  while (true) {
    loop.context.applySoftForgetting();
    if (loop.context.nearLimit()) yield* loop.compact();        // 硬压缩
    if (loop.constraints.nearDeadline()) loop.injectWrapUpWarning(); // 优雅终止
    if (loop.constraints.exceeded()) { yield* loop.finalize(); return; }

    const turn = loop.model.stream(loop.context.build(), loop.abortSignal); // ModelRouter 选角色
    for await (const chunk of turn) {
      yield* mapChunks(chunk);                                   // text_delta / tool_call
      if (loop.hardInterrupted()) { loop.abort(); return; }      // Esc：取消模型与当前工具
    }

    if (turn.toolCalls.length === 0) {                           // 模型宣布完成/提问
      yield turn.asksUser ? { type: 'need_user', ... } : { type: 'done' };
      return;
    }

    for (const call of turn.toolCalls) {
      const verdict = loop.permissions.judge(call);              // 权限判定
      if (verdict === 'ask') {
        const answer = yield* loop.requestPermission(call);      // 等待批准（可超时拒绝）
        if (!answer.granted) { turn.deny(call); continue; }
      }
      const result = await loop.tools.execute(call);             // 执行 + 截断
      loop.context.appendResult(call, result);
      yield { type: 'tool_result', ...result };
    }

    loop.dequeueUserMessages();                                  // 软打断消息注入下一轮
  }
}
```

### 2.3 todo 工具

- 接口：`todo_write(todos: TodoItem[])` 全量写，不做增删改三个接口
- 状态机 `pending → in_progress → completed`，同一时刻仅一个 `in_progress`，约束写进工具说明由模型遵守
- todo 存为独立状态，不入对话历史
- **注入方式（缓存前缀工程）**：todo 作为独立 user 消息注入 messages，插在最后一条 user 消息之前——**绝不进 system**。todo 随 TodoWrite 高频变化，若进入 system，一字节变化会让其后整个 messages 历史的 prompt cache 失效；放消息尾部只影响尾部缓存
- 触发时机：系统提示约定"任务超过约 3 步先建 todo"，不写 if-else

### 2.4 无人值守：任务盒与优雅终止

**任务三要素指令**（无人值守的指令必须可机器验收）：

```
/run 提升检索质量 \
  --goal  "检索评测达到目标质量" \
  --check "pnpm test:eval" \
  --bounds "不改 src/api/，不动数据库 schema" \     # 负面清单
  --until 07:00 --budget 5 --permission trust       # 时间盒/预算盒/权限档
```

（shell 层仅 `myagent` 与 `myagent --web` 两个入口；`/run` 是 CLI 内部命令，任务在当前会话中持续运行）

- `--goal`：任务目标描述；`--check`：系统在 Agent 声明完成后实际执行的验收命令，可重复声明并按顺序运行。失败输出会反馈给 Agent，最多自动修复 2 轮；检查通过且有任务期文件改动时自动运行独立 Completion Review，不受默认关闭的普通任务审查开关影响。
- **`--bounds` 双轨处理**（诚实区分硬/软约束）：
  - **路径类**（如"不改 src/api/"）：由模型翻译成候选 deny 规则，**任务启动前展示清单给用户确认一次**（无人值守出发前的最后一次同步检查），确认后成为会话级硬规则，任务结束失效；中文全量语义（"不改任何文件 / 整个项目"）编译为 Edit/MultiEdit/Write 的全量 deny（`Edit(**)` 等），避免 fail-unsafe
  - **语义类**（如"不动数据库 schema"）：任何路径规则都表达不了——注入为系统提示强约束，文档明确其"非硬规则"性质
- `--permission` 为**任务期临时档位**，任务结束回落会话原档位
- 时间/预算约束由 AgentLoop 每轮检查

**分阶段优雅终止**（阶段可配，默认 `[30, 10, 2]` 分钟）：

| 时间点 | 注入内容（system 角色追加） | 期望行为 |
|---|---|---|
| 剩余 30 分钟 | "评估进度，停止开新的大改动，优先完成手头闭环" | 收窄范围 |
| 剩余 10 分钟 | "立即收尾：①确保代码可编译/测试通过 ②更新 todo ③写入记忆 ④生成总结" | 收尾模式 |
| 剩余 2 分钟 | "停止一切工具调用，立即输出总结" | 纯文本输出 |
| 归零 | 硬终止（兜底，正常到不了） | — |

- 每次警告同时发 `wrapup_warning` 事件（监控台可见"进入收尾"）
- **收尾目标是"可编译状态"**：优先完成当前闭环；确需撤销时只使用 EditJournal 保存的逆向补丁，并且仅在文件当前哈希仍等于 Agent 写入后的哈希时执行。禁止用 `git checkout`、`git reset` 等宽泛命令清理工作区；无法安全恢复时保留现场并在总结中明确报告
- 预算盒同理，但首次警告更早（剩余 ~30% 预算即注入，因花钱是连续的）

**收尾三件套**（固定格式产出）：
1. 总结报告（干了什么、验证结果前后对比、遇到的坑）
2. todo 快照（完成/未完成/卡点，供下次续干）
3. 记忆写入（本次学到的稳定事实）

## 3. 工具协议

### 3.1 Read

```
Read(file_path, offset?, limit?)
→ 带行号内容（cat -n 格式），默认上限 2000 行，单行截 2000 字符
→ 副作用：登记"已读文件"集合
```

### 3.2 Edit

```
Edit(file_path, old_string, new_string, replace_all?)
约束：必须先 Read 过该文件；old_string 精确匹配且唯一（replace_all 除外）
成功：返回改动处上下文片段（diff 视图）
失败：明确报错（未找到 / 匹配 N 处），交给模型自愈
```

### 3.3 MultiEdit

```
MultiEdit(file_path, edits: [{old_string, new_string}...])
顺序应用，任一失败整体回滚，保证文件不处于"改了一半"状态
```

### 3.4 Write

```
Write(file_path, content)
新文件或大段重写；覆盖已存在文件也要求先 Read
```

### 3.5 Bash

```
Bash(command, timeout?, background?)
→ 默认：输出流式；超时或 Esc 时先终止整个进程组，宽限期后强杀
→ background=true：以 detached 进程组后台启动（stdio 忽略），立即返回 {pid}，
  不阻塞主循环、不采集输出；如需查看状态或输出，另行运行 ps / 日志命令
→ 只保证进程停止，不承诺撤销命令已经产生的文件、网络或外部系统副作用
```

### 3.6 工具结果统一策略

- 行数 + 字符双上限（如 256 行或 30KB 取小）
- **留头尾、掐中段**（错误信息通常在尾部），截断处插入显式标注：
  `[... N lines truncated, use offset=M to continue ...]`
- 标注必须"机器可续读"——告诉模型用什么参数接着看

## 4. 上下文管理实现

### 4.1 软遗忘

- 每轮组装前扫描历史：超过最近 N 轮（如 3 轮）的工具结果，内容替换为占位符：
  `[此前 Read src/auth.ts 的输出已省略，共 412 行。如需再看请重新 Read。]`
- 对话本体（模型文本、用户消息）永不遗忘
- 占位符必须包含恢复指引，不做静默删除

### 4.2 硬压缩

- 触发：token 估算达窗口 90%（自动）或用户手动 `/compact`
- 流程：全对话发给 `cheap` 角色模型 → 产出结构化摘要（任务目标 / 已完成的改动 / 关键文件与行号 / 当前 todo / 用户偏好）→ 新上下文 = 摘要 + 最近 4 轮原文
- 产出 `context_compacted` 事件并写入 JSONL，resume 时从摘要重建

### 4.3 repo map

- tree-sitter 解析仓库 → 签名级地图（文件路径、类、函数签名，无实现）
- 常驻系统提示，目标控制在几千 token；大仓库按目录折叠，模型可用 Glob 下钻

### 4.4 prompt caching

**核心原则：前缀稳定工程**——缓存命中的物理条件是两次请求的 prompt 前缀字节级一致，因此把高频变化内容移出前缀、稳定内容保持字节不变。

- **system 只放低频稳定内容**：基础系统提示 + AGENTS.md + 记忆文件 + repo map + 跨项目索引（低频，文件不变则字节不变）
- **记忆类静态段会话内只构建一次**（参照 Pi 的 AGENTS.md 启动时加载）：AGENTS.md / 全局记忆 / 项目记忆 / 跨项目索引在会话首次 prepare 时组装并缓存，agent 运行中写记忆**不刷新当前会话 system**（下次会话生效）——前缀字节级稳定，且跨会话也能命中 DeepSeek 全局缓存
- **跨项目索引会话内只生成一次**：避免每轮重扫其他项目目录（既省 IO 又防内容抖动破坏前缀）
- **todo 移出 system**：作为独立 user 消息注入 messages 尾部（见 §2.3），高频变化只影响尾部缓存
- **Anthropic 渠道设置 `cache_control` 断点**；OpenAI 兼容端点（DeepSeek 等）依赖整段前缀自动缓存
- 实测效果（三阶段）：修复前第 2 轮 4% → todos 移出 system 后 66.4% → 静态段固定后 system 唯一值 1、第 1 轮命中 **97.2%**（跨会话缓存命中）、第 2 轮 65.6%（新增消息部分天然无法命中，接近结构上限）

## 5. 会话持久化方案

### 5.1 JSONL 结构

每行一个事件，带全局序号与时间戳：

```json
{"seq":1,"ts":"...","type":"user","text":"修一下登录bug"}
{"seq":2,"ts":"...","type":"tool_call","tool":"Read","args":{...}}
{"seq":3,"ts":"...","type":"tool_result","ref":2,"summary":"...","truncated":false}
{"seq":4,"ts":"...","type":"todo_update","todos":[...]}
{"seq":9,"ts":"...","type":"context_compacted","summary":"...","keepFromSeq":7}
{"seq":10,"ts":"...","type":"cost_update","model":"claude-sonnet","in":12000,"out":800}
```

### 5.2 resume 算法

1. 顺序读文件，遇 `context_compacted` 则丢弃 `keepFromSeq` 之前的原始消息、插入摘要
2. 重放剩余消息 + todo 快照重建上下文
3. "本次会话允许"的批准集合仅存内存、不落盘，进程重启即清空（与 TC-C2 一致：重启后仍问）

### 5.3 会话索引

会话元数据（标题、权限档、成本）**只存事件流**，不维护索引文件（index.json 已废除，2026-08 起）：列表页从各会话文件的 `session_info` / `permission_mode_changed` / `cost_update` 事件重建（标题另经 `cheap` 模型生成）：

- 系统提示要求"简短中文标题（10 字以内）"，模型输出经 `clipTitle` 清洗标点并按长度智能截断（**优先在单词/分词边界切断**，避免英文残词如 "explori"）
- **语言守卫**：用户请求为中文而模型返回纯英文标题时，回退到请求原文前缀
- **失败兜底**：标题生成失败（超时/报错）时用首条消息前缀兜底，不永远停在「新会话」

## 6. 权限引擎实现

### 6.1 判定逻辑

```ts
interface PermissionRule { effect: 'allow'|'ask'|'deny'; pattern: string }  // 如 "Bash(npm test *)"

judge(call: ToolCall): 'allow' | 'deny' | 'ask' {
  if (matchAny(config.deny, call)) return 'deny'
  if (session.mode === 'strict' && isWriteOrBash(call)) return 'ask'
  if (matchAny(config.ask, call)) return 'ask'
  if (matchAny(config.allow, call)) return 'allow'
  if (session.mode === 'trust') return 'allow'
  if (session.mode === 'normal' && isNormalAutoAllowed(call)) return 'allow'
  if (session.mode === 'strict' && isReadOnly(call)) return 'allow'
  return 'ask'
}
```

- 固定优先级：`deny > strict 档 > ask > allow > trust 档 > normal 默认策略`
- `isNormalAutoAllowed` 包含 Read / Grep / Glob / Edit / MultiEdit；Bash 必须命中安全 allow 规则才自动放行；Write 默认 ask
- 出厂默认规则：只读命令（ls/cat/grep/git status/diff）+ 常见构建测试 → allow；网络写入、删除、git push、全局安装 → ask/deny；`Edit(~/.ssh/**)` 等敏感路径 → deny
- deny 直接返回工具错误并回灌模型，不产生审批请求；任何档位都没有临时强制放行入口
- 批准选项：`仅一次 / 本次会话 / 本项目 / 全局`，后两级写入对应层 config.jsonc，热生效
- `ask_permission` 无人响应超时（可配，默认 5 分钟）→ 自动拒绝
- 无人值守任务的 `--bounds`：路径类翻译为候选 deny 规则、启动前经用户确认后生效（会话级，任务结束失效）；语义类不在此层，走系统提示强约束（见 §2.4）

### 6.2 审批内容协议（看完再批，3 秒知情）

原则：**少量但认真的审批**——弹得少，用户才愿意每次细看；弹多了会养成"盲批"习惯，审批失效。

- **Edit / Write：批准前渲染真实 diff**（old/new 本就确定，非预测）
  - 默认显示改动块 ±3 行上下文；>50 行折叠为统计可展开
  - Write 新文件：显示"新建 xxx（N 行）"+ 前 20 行预览
- **Bash：副作用无法预演，做风险翻译**
  - 审批卡片 = 命令原文 + 一行风险翻译 + Agent 的目的（一句原话）
  - 风险翻译来自可扩展的规则库：`npm test`→"通常无副作用"；`npm install x`→"将修改 package.json 与 lock 文件"；`rm -rf`→"⚠ 递归删除"；`git push`→"⚠ 推送远程，不易撤销"；未命中→"副作用未知，请自行判断"（未知本身也是信息）
- **拒绝可留言**：第四选项"拒绝并留言"（如"别用 npm 用 pnpm"），拒绝原因回灌模型立即换方案，省一轮重新打字
- 档位配合：strict 档 Edit / MultiEdit / Write / Bash 均弹审批（带 diff 或风险翻译）；normal 档 Edit / MultiEdit 自动放行，Write 与 Bash 灰区弹审批

### 6.3 原子编辑与 EditJournal

- Edit / MultiEdit / Write 均先在同目录临时文件写入完整新内容并 `fsync`，再原子 rename；中止发生在 rename 前则保留旧文件，发生在 rename 后则得到完整新文件
- 每次成功编辑记录 `{path, beforeHash, afterHash, reversePatch}`，供任务收尾精确撤销
- 自动撤销前重新计算当前哈希；仅当等于 `afterHash` 时应用逆向补丁，避免覆盖用户或其他进程的后续修改
- Bash 产生的改动不进入 EditJournal，不能自动撤销

## 7. 模型路由实现

```ts
interface ModelProvider {
  stream(req: ChatRequest): AsyncIterable<Chunk>
  countTokens(messages): number
}

// 配置：渠道注册表 + 角色选择，支持多个第三方 OpenAI-compatible 端点
providers: [
  { id: 'anthropic', protocol: 'anthropic', baseUrl: 'https://api.anthropic.com', models: ['...'] },
  { id: 'deepseek', protocol: 'openai-compatible', baseUrl: 'https://api.deepseek.com/v1', models: ['deepseek-chat'] },
  { id: 'moonshot', protocol: 'openai-compatible', baseUrl: 'https://api.moonshot.cn/v1', models: ['kimi-k2'] },
]
models: {
  main:    { providerId: 'anthropic', model: 'claude-sonnet-4-...' },
  cheap:   { providerId: 'deepseek', model: 'deepseek-chat' },
  explore: { providerId: 'moonshot', model: 'kimi-k2-...' },
}
```

- 角色在调用点显式指定：主循环用 `main`、压缩/标题用 `cheap`、TaskRunner 用 `explore`（Task 可覆盖）
- **成本控制是主干，成本展示是辅助**：每次调用记录 usage（含缓存命中）写入 JSONL——这是预算熔断与审计的基础；展示层保持克制：
  - **每轮对话末尾**显示一行小字：`本轮 12.4k in / 1.8k out · 缓存命中 78% · 累计 89k`（token 为主、金额为括号小字）
  - `/cost` 命令输出会话累计；会话卡片与通知带一行成本
  - **不做独立仪表盘页面**、不做聚合图表与诊断建议；数据全量在 JSONL，需要时可随时加展示层
- 预算熔断：会话累计花费 ≥ 预算盒 → 注入终止警告并走优雅终止流程

### 7.1 模型调用容错（无人值守的命脉）

通宵任务遇 429/500/断网的行为定义：

- **重试**：回合级指数退避（2s 起步，默认 3 次，可配置；overflow 特例先强制压缩再重试一次）；429 尊重 `Retry-After` 头
- **fallback 链**：每个角色可配有序模型列表（如 `main: [claude-sonnet, deepseek-chat]`），主模型持续失败自动降级到下一个，事件流中可见降级记录
- **持续失败兜底**（重试与 fallback 全部耗尽）：
  - 交互模式：挂起并询问用户（`need_user`）
  - 无人值守：`notify(error)` + 触发优雅终止收尾（保留现场，人来了再续）

### 7.2 多供应商成本核算口径

- **对账唯一事实源：API 返回的 usage**；本地 token 估算仅用于预算熔断的触发判断（TC-D2 的"误差 <5%"即以此口径衡量）
- 价格表内置于配置（每模型：单价 + 币种），可手动更新；金额归一化为人民币显示（汇率作为配置项）
- 无官方 tokenizer 的供应商：以 API usage 为准，估算仅作熔断参考

## 8. 子代理（Task）协议

```
Task(description, prompt, model?, writable?)
```

- **发起**：主 Agent 自写完整 prompt（系统提示教它"假设对方对会话一无所知"）
- **运行**：嵌套 AgentLoop；默认只读工具集；`writable` 显式开启写权限；审批冒泡到主会话 UI；嵌套 ≤2 层、并发 ≤4、最多 40 轮强制收尾（成本兜底）、可设 token 预算
- **回流**：仅最终结论作为工具结果，要求三段式输出（结论 / 关键证据(文件:行号) / 未能确认的部分）
- **失败**：崩溃、超时、超预算一律消化为工具结果返回主 Agent（含部分结论与已覆盖范围），绝不上抛中断主循环
- **观测**：`task_start/task_event/task_end` 事件族，`task_end` 携带独立成本归因

## 8.5 项目初始化（/init）

原则：**进入陌生项目默认零操作**（零风险、零 token），一切了解项目的行为由用户显式触发。

```
/init 流程：
  1. 子代理（explore 便宜模型）只读扫描：目录结构、package.json/配置、README、入口文件
     —— 探索不进主上下文，只回流结论
  2. 生成 AGENTS.md 草稿展示给用户：技术栈 / 常用命令（安装·构建·测试·lint）/
     目录导览 / 检测到的约定
  3. 用户确认或编辑后保存（保存本身是一次审批）
```

- /init 是可选的：从未 init 也能干活（现用现探索）；init 的价值是一次性固化常识，之后每次会话省掉重复探索
- repo map 同样惰性构建：第一次代码探索任务时才生成，增量更新，不在 /init 时全量建
- 项目大变后可重跑 /init：覆盖前展示新旧 diff，仍须用户确认

## 8.6 记忆存储（MemoryStore）实现方案

**写入**：复用 Edit 工具，零新增机制。触发时机两种：①干活中学到稳定事实时自主写入；②优雅终止收尾三件套中的强制写入。条目格式：

```markdown
- [2026-07-29] Chroma 连接必须显式 timeout=10s（来源：会话 #a3f9）
- [2026-07-28] Nightwatch 评测需 --workers=1 【待验证：仅观察过一次】
```

**注入策略**（会话首次组装系统提示时构建一次并缓存，见 §4.4）：
- 全局 `MEMORY.md` + 当前项目三个记忆文件：全文注入，单文件预算 ~200 行，超预算由模型自行整理合并（写入时自律）
- **会话中写入的记忆不刷新当前会话**（静态段缓存）：当前会话 system 保持字节级稳定以最大化缓存命中，新记忆下次会话生效
- **跨项目标题索引**：遍历 `~/.myagent/projects/` 下其他项目记忆目录，仅注入"项目名 + 文件路径 + 条目标题"（几十行）；**会话内只生成一次并缓存**——避免每轮重扫其他项目目录破坏 system 前缀缓存（见 §4.4）

**跨项目调取**：零新增工具——索引中携带完整路径，模型判断相关时直接用 Read 读对应记忆文件全文（TC-H2 依赖此路径）

**治理**：见功能文档 §6.1 三层防线（写入可见 / 写入自律 / 删除即治理）

## 9. 配置 Schema 方案

**文件格式：JSONC**（JSON with Comments，VS Code 配置文件同款格式）。

- 语法与 JSON 完全一致，仅增加 `//` 与 `/* */` 注释支持——权限规则、模型选择这类"三个月后自己都忘了为什么"的配置，注释是真需求
- 解析用 `jsonc-parser`（VS Code 官方库）
- **机器写回时保留用户注释**：用 modify（编辑而非重写）方式只改目标字段，不重排整个文件

```ts
// 一份 Schema 定义全部配置项，CLI/Web 界面自动生成
const ConfigSchema = {
  'providers':          { type: 'provider[]', hot: true, desc: 'Anthropic / OpenAI-compatible 渠道注册表' },
  'models.main':        { type: 'role-model', hot: true, desc: '主循环模型（providerId + model）' },
  'models.cheap':       { type: 'role-model', hot: true, desc: '压缩/摘要模型' },
  'models.explore':     { type: 'role-model', hot: true, desc: '子代理探索模型' },
  'permissions.mode':   { type: 'enum', values: ['strict','normal','trust'], hot: true },
  'permissions.rules':  { type: 'rule[]', hot: true,  desc: 'allow/ask/deny 规则表' },
  'context.compactAtEstimatedTokens': { type: 'number', default: 90000, hot: false, desc: '硬压缩触发阈值（估算 token 数）' },
  'server.host':        { type: 'string', default: '127.0.0.1', hot: false },
  'server.password':    { type: 'secret', hot: false, desc: '外部访问密码（监听非 localhost 时必填）' },
  'notify.webhook':     { type: 'string', hot: true,  desc: '通知 webhook 地址' },
  // ...
}
```

分层合并（四层）：`CLI 参数 > 项目本地（<repo>/.myagent/local.jsonc，gitignore）> 项目共享（<repo>/.myagent/config.jsonc，可进 git）> 全局（~/.myagent/config.jsonc）> Schema 默认值`。
"本项目永久允许"的批准规则写入项目本地层——个人授权不随仓库提交。
`hot: true` 的项改完即生效；`secret` 类型 UI 脱敏显示。

**模型配置热生效**：配置变更（含 API Key、模型、fallback 链）通过 `configService.onChange` 触发——每个运行中会话用最新配置重建 main/cheap/explore 三个模型客户端并替换（`ConversationAgentModel.setClient` / `setCompactionClient`、`TaskRunner.setClient`），会话历史不丢失。改 API Key 无需重启会话或新建会话。

## 10. Web API 方案

| 端点 | 说明 |
|---|---|
| `GET /api/sessions` | 会话列表（扫描会话文件 + 事件重建元数据） |
| `POST /api/sessions` | 新建会话（可带任务盒参数） |
| `GET /api/sessions/:id/stream` | SSE：订阅事件流（fromSeq 增量拉取） |
| `POST /api/sessions/:id/input` | 发送用户消息 / 软打断 |
| `POST /api/sessions/:id/permission` | 审批答复（含记忆级别选项） |
| `POST /api/sessions/:id/interrupt` | 中止当前模型与工具执行 |
| `GET/PUT /api/config?scope=global\|project` | 配置读写（走 ConfigService） |
| `GET /api/config/schema` | 配置 Schema（前端自动生成表单） |
| `POST /api/config/test?scope=global\|project` | 对指定 providerId + model 发最小真实请求，返回连通性、错误分类与延迟 |
| `GET /api/memory` / `PUT /api/memory/:file` | 记忆浏览与编辑 |

**认证**（仅当监听非 localhost 时启用）：访问密码校验后签发 HttpOnly Cookie 会话（7 天有效），REST 与 SSE 均同源 Cookie 携带，无需额外 token 机制。LAN 明文 HTTP 接受为当前版本现状（内网信任域，文档明示）；需 HTTPS 时由用户自建反向代理。

## 11. 通知方案

**分层设计：页面内通知为主（默认），外部推送为辅（已实现）。**

- **页面内**：审批卡片、会话状态变化、浏览器标签页标题提示（如 `(1) 等待审批`）。纯 Web 使用零配置开箱即用
- **外部 webhook（已实现）**：为"人离开屏幕且不想主动查看"的无人值守场景设计。事件订阅者（监听 `done` / `notify(error)` / 审批超时），通用 webhook POST 对接企业微信 / 飞书 / Bark / 任意 JSON 网关；不配即不存在，Core 与 Web 均不依赖。推送纪律：只推"需要你知道"的（完成/出错/超时），不推主动汇报；同一任务每小时最多 2 条。另有 macOS 桌面通知（`notify.desktop`）

## 11.5 可观测性

原则：**全量 JSON trace 落盘，不做日志分级、不做指标聚合、不做查看界面**。磁盘便宜，排查时缺数据才贵。

两份文件分工：

```
~/.myagent/projects/<项目>/sessions/
    <session-id>.jsonl        ← 产品事件流（恢复/resume 用）
    <session-id>.trace.jsonl  ← 工程 trace（排查问题用）
```

trace 每轮一条完整 JSON：`{turn, ts, request(发给 API 的完整 payload), response(模型原始返回), tools:[{call, permission, result, ms}], usage}`。

- **无条件全量**：工具结果在 trace 中不截断（截断只发生在发往模型的路上，trace 要真相）
- 工程调试的终极手段一句话："去看第 N 轮的 request——它当时看到什么，就是什么"
- 查看方式：VS Code 直接打开；以后需要再加界面

## 12. 实施策略

**Core 抄成熟，外围先见效**。顺序原则：先做不碰循环的外围（token 透明 → 结构化记忆 → 多供应商），再做 Web 只读监控台，最后做深入循环的任务盒与优雅终止；通知 webhook 与桌面通知已实现。全程守住纪律：外围只通过 Core 公开接口接入。
