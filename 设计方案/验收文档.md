# MyAgent — 验收文档

> 验收以"用户怎么使用"为主线组织测试用例。每条用例包含：前置条件、操作步骤、通过标准。

## 验收状态总览

> 更新时间：2026-08-02（一期收官，已推送远程 github.com/zishuo-xu/gpt_agent）

每节用例的详细通过标准见下。

## A. 基础闭环

### TC-A1 修复一个真实 bug（核心价值验证）
- **前置**：任意含测试的 Python/JS 项目，存在一个会失败的测试
- **操作**：项目目录下 `myagent`，输入"修一下这个报错的测试：npm test 里 login 那个用例"
- **通过标准**：
  1. Agent 自主定位相关源文件（过程中有 Read/Grep 调用）
  2. 使用 Edit 精确修改，界面展示 diff
  3. 自主运行测试验证；若仍失败，自行迭代直到通过
  4. 宣布完成时给出改动摘要
  5. 全程无人工介入超过 2 次（批准除外）

### TC-A2 多步骤任务与 todo 可视化
- **操作**：输入"给这个项目加上 ESLint 配置，修掉所有 error，并把 npm run lint 加进 CI 配置"
- **通过标准**：任务开始后 todo 面板出现 ≥3 项清单；同一时刻仅一项 in_progress；随执行实时翻转为 completed；最终 lint 通过、CI 文件被正确修改

### TC-A3 编辑安全性
- **操作**：让 Agent 修改一个它尚未 Read 的文件（可诱导："直接把 config.yaml 的 port 改成 8080"）
- **通过标准**：Edit 被拒绝并提示需先 Read；Agent 自行 Read 后再改成功
- **操作**：让 Agent 替换一段在文件中出现 3 次的字符串
- **通过标准**：报"匹配多处"错误；Agent 给出更长上下文使匹配唯一后成功

### TC-A4 /init 项目初始化
- **操作**：在陌生项目中启动，不做任何操作直接问一个简单问题
- **通过标准**：Agent 不自动扫描项目（无大范围 Read/Grep），直接回答问题
- **操作**：输入 `/init`
- **通过标准**：扫描由子代理执行（主上下文无探索全文）；产出 AGENTS.md 草稿（技术栈/常用命令/目录导览/约定）；确认前不落盘；编辑后保存的版本与下次会话注入内容一致
- **操作**：从未 /init 的项目中直接派一个编码任务
- **通过标准**：任务可正常完成（现用现探索）

## B. 上下文与长会话

### TC-B1 软遗忘不丢关键信息
- **操作**：连续让 Agent 读 10 个大文件，之后再问"第三个文件里那个函数叫什么"
- **通过标准**：老工具结果已占位符化（token 占用显著下降）；Agent 通过重新 Read 恢复信息后正确回答

### TC-B2 硬压缩后可继续
- **操作**：长会话接近上下文上限（或用低阈值配置模拟）触发自动压缩，随后继续下达依赖前文背景的新指令
- **通过标准**：界面出现压缩提示与比例；压缩后 Agent 仍记得任务目标、已完成的改动与 todo 状态，新指令执行正确

### TC-B3 会话恢复（/switch）
- **操作**：一次任务做到一半直接 `Ctrl+C` 杀掉进程；重新 `myagent` 后 `/switch` 选择该会话
- **通过标准**：会话完整重放（含 todo 状态）；输入"继续"后 Agent 从断点接着干，不重复已完成的步骤

### TC-B4 打断
- **操作**：Agent 执行中输入一条新指令（不打断），观察其在本轮结束后响应；再次执行中按 Esc
- **通过标准**：软打断消息在当轮结束后被处理；Esc 立即取消模型与当前工具；Edit / MultiEdit / Write 中止后文件要么保持旧版本、要么是完整新版本，不存在半文件；Bash 整个进程组被终止，界面提示其已发生的副作用无法自动撤销

## C. 权限

### TC-C1 三档行为
- **通过标准**：strict 档下 Edit / MultiEdit / Write 与所有 Bash 均弹批准且忽略 allow 记忆；normal 档下 Edit / MultiEdit、`ls`/`npm test` 自动放行，Write 与 `git push` 弹批准；trust 档下 deny 被直接拒绝、显式 ask 仍弹批准，其余自动放行

### TC-C2 批准记忆四级
- **操作**：对 `git commit *` 依次验证四个选项
- **通过标准**："仅一次"下次仍问；"本次会话"重启后仍问、会话内不再问；"本项目"写入项目 config 且新会话不再问但其他项目仍问；"全局"任意项目不再问；四类规则在 Web 设置页可见可删

### TC-C3 黑名单豁免不存在
- **操作**：trust 档下诱导 Agent 执行 `rm -rf` 类命令
- **通过标准**：直接拒绝且不出现临时强制放行入口；工具错误回灌 Agent 后必须换方案

### TC-C4 无人值守 fail-closed
- **操作**：normal 档起一个任务，出现审批请求后不响应
- **通过标准**：超时（默认 5 分钟）自动拒绝，Agent 换路继续或优雅收尾，不僵死

### TC-C5 审批内容（看完再批）
- **操作**：strict 档下让 Agent 修改一个文件，观察审批卡片
- **通过标准**：批准前展示真实 diff（±3 行上下文），diff 与最终落盘完全一致；大改动折叠为统计可展开
- **操作**：触发一次 `npm install xxx` 审批
- **通过标准**：卡片含命令原文、风险翻译（"将修改 package.json 与 lock 文件"）、Agent 的目的；未识别命令显示"副作用未知"

### TC-C6 拒绝并留言
- **操作**：审批时选"拒绝并留言"，填"别用 npm，用 pnpm"
- **通过标准**：工具未执行；留言回灌后 Agent 下一条命令改用 pnpm

## D. 无人值守

### TC-D1 时间盒 + 优雅终止
- **操作**：交互界面中 `/run 持续优化测试覆盖率 --goal "pnpm test 全过" --bounds "不改 src/api/" --until <当前时间+40分钟> --permission trust`
- **通过标准**：
  1. 三个阶段依次出现（收窄范围 → 进入收尾 → 只输出总结），事件流可见 `wrapup_warning`
  2. 收尾优先使代码处于可编译/测试通过状态；需要撤销时只能通过 EditJournal 撤销 Agent 自己且未被再次修改的编辑，禁止宽泛 `git checkout/reset`；无法安全恢复时保留现场并报告
  3. 产出三件套：总结报告（含验证结果对比）、todo 快照、记忆写入
  4. 启动前展示了 bounds 编译出的候选 deny 规则清单并经确认；清单与 bounds 语义一致；`--bounds` 中的目录全程未被修改
  5. `--permission trust` 在任务结束后回落会话原档位，后续交互不受影响

### TC-D2 预算盒熔断
- **操作**：设置极小 `--budget` 跑一次任务
- **通过标准**：花费达上限触发优雅终止；以 API 返回 usage 为对账口径，累计 token 与之一致（误差 <5%）

### TC-D3 通知
- **操作**：起一个会完成的短任务，保持 Web 页面打开
- **通过标准**：页面内状态实时变为"已完成"，标签页标题出现提示；全程无需任何外部配置
- **（后续扩展）**：配置 webhook 后跑任务，完成时收到外部推送，含任务摘要与会话链接；出错任务收到 error 级推送

## E. Web 界面

### TC-E1 监控台
- **操作**：同时跑两个会话（一个交互一个 `/run` 任务），打开 `myagent --web`
- **通过标准**：首页两张状态卡，进度/花费/时长实时刷新；数据与 CLI 端一致

### TC-E2 会话详情与回放
- **操作**：进入一个已完成会话，开启回放模式
- **通过标准**：可从第一条事件顺序复盘全部决策（文本、工具、diff、子代理卡片齐全）

### TC-E3 远程审批（手机场景）
- **前置**：配置监听内网 IP + 访问密码
- **操作**：手机浏览器打开 Web，触发一次审批请求
- **通过标准**：无密码无法访问；输入密码后看到审批卡片；点"允许"后 Agent 端立即继续（≤2 秒）

### TC-E4 配置界面自动生成
- **操作**：在 Config Schema 中新增一个配置项（不改任何前端代码），刷新设置页
- **通过标准**：新配置项自动出现在设置页，类型控件正确，保存后生效（hot 项立即生效）

### TC-E5 记忆面板
- **操作**：跑一个任务让 Agent 写入至少一条记忆，打开记忆面板
- **通过标准**：能看到该条记忆及"它学到了什么"时间线记录；手动编辑后下次会话生效

## F. 模型与成本

### TC-F1 多供应商切换
- **操作**：将 explore 角色配置为 OpenAI 兼容端点（如 DeepSeek），触发一次子代理探索
- **通过标准**：子代理正常完成；该轮 token 计入会话累计
- **操作**：在 Web 设置页为同一供应商配置两个模型，分别点击各自的“测试连接”
- **通过标准**：两次测试明确显示实际模型名、延迟与独立结果；认证失败、模型/路径错误、限流/额度不足、网络不可达有可区分提示

### TC-F2 每轮 token 透明
- **操作**：进行一次多轮对话，观察每轮回复末尾的小字
- **通过标准**：每轮显示 in/out token、缓存命中率、会话累计；数值与 API 返回 usage 一致；`/cost` 输出与逐轮累计吻合

## G. 子代理

### TC-G1 上下文隔离有效性
- **操作**：让 Agent "全面搜索这个仓库的鉴权相关代码"
- **通过标准**：主上下文中只出现结论（含 文件:行号 证据），不出现搜索过程的全文；主会话 token 增量远小于直接搜索（数量级差异）

### TC-G2 子代理失败降级
- **操作**：构造一次子代理中途失败（如超时）
- **通过标准**：主循环不中断；主 Agent 收到"部分结论 + 失败说明"并决定重试或自己完成

## H. 记忆复利

### TC-H1 跨会话记忆
- **操作**：会话 1 中告诉 Agent "这个项目用 pnpm，别用 npm"（Agent 应写入记忆）；开新会话让 Agent 安装依赖
- **通过标准**：新会话中 Agent 直接使用 pnpm，无再次询问

### TC-H2 跨项目联想
- **操作**：项目 A 的记忆中已有一条 Chroma 踩坑记录；在项目 B（也用 Chroma）遇到相似问题
- **通过标准**：Agent 通过标题索引发现项目 A 的记忆并调取全文，给出包含该经验的解决方案

### TC-H3 记忆治理
- **操作**：任务后打开记忆面板，找到一条错误记忆并删除；另在对话中指出"上次你记的 XX 是错的，删掉"
- **通过标准**：面板删除即时生效且下次会话不再注入；对话中指正后 Agent 自行修正记忆文件；每次自动写入在时间线中可审计

## I. 任务启动（/run）

### TC-I1 /run 一次性任务
- **操作**：交互界面中 `/run 清理所有 console.log`（normal 档，不加约束）
- **通过标准**：任务在当前会话持续运行直至完成，输出总结（改动统计 + 测试结果）；记忆/todo 照常写入；`/switch` 切走再切回，会话内容完整

### TC-I2 入口收敛
- **操作**：检查 shell 层可用命令
- **通过标准**：仅 `myagent` 与 `myagent --web` 两个入口；无 `-p`/`run`/`resume` 等 shell 子命令；任务、恢复全部通过内部命令完成
