# MyAgent — Agent Harness 目标与愿景

## 一句话

> **一个 local-first Agent Harness：让工具型 Agent 的每次运行都可追踪、可分叉实验、可对比、可评测，并由系统证据判定是否真正完成。**

## 我们在做什么

MyAgent 的产品主体是 Harness，不是某一个 Prompt 或模型。当前 TypeScript Coding Agent 是随项目内置的第一个 Runtime，用来把模型调用、工具执行、权限、持久化、机器验收和调试实验跑成一个真实闭环。

终端里敲 `myagent` 可以交互或用 `/run` 启动长任务；`myagent --web` 除了监控、审批和回放，还能查看 Turn 级 Trace，从任意可复现 Turn 创建隔离实验，修改模型与 System Prompt Overlay，并比较父子 Run 的首个行为分歧。

## 为什么需要 Agent Harness

单个 Coding Agent 只能回答“这次看起来做完了吗”；Harness 要回答更工程化的问题：它实际看到了什么、调用了什么、为什么在这里开始偏离、换模型或 Prompt 是否更好、相同目标能否稳定通过机器验收。

| 我们的差异 | 解决什么 |
|---|---|
| **模型自由 + 自动路由** | 不锁单一厂商；探索子任务用便宜模型，摘要压缩用便宜模型，长任务成本降一个量级 |
| **无人值守形态** | 时间盒 + 预算盒 + 优雅终止协议；Web 监控台随时看进度；手机端审批；跑完推送通知 |
| **结构化记忆** | 项目约定、踩坑记录、架构决策分类型沉淀，跨会话、跨天、跨项目复利——越用越懂你 |
| **Flight Recorder** | Turn 与事件流可靠关联；默认脱敏查看完整请求、响应和工具阶段 |
| **隔离实验与 Run Diff** | 从指定 Turn 重建对话，在 Git worktree 中固定模型和 Overlay 立即运行，定位首个 `tool + target` 分歧 |
| **可信完成** | Agent 声明完成不等于系统完成；`--check` 和独立 Review 产出 Evidence Bundle |

这些能力指向同一个定位：**MyAgent 不是只提供一个会写代码的 Agent，而是提供观察、控制、复现和评测 Agent 的本地实验基础设施。**

## 设计信条

1. **Core 抄成熟的，创新做在外围** —— 主循环、工具协议、上下文管理对齐 Claude Code；差异化全部在产品层，不赌底层发明。
2. **单引擎双前端** —— Core 是唯一大脑，CLI 和 Web 都是薄壳，零重复逻辑。
3. **一切可观测且可关联** —— 事件流 + versioned Trace + JSONL 持久化，每个 Turn 能落回事件范围、工具序列和实际模型。
4. **失败要响，不要静** —— 编辑要么成功要么明确报错；权限拿不准就问；无人值守超时自动拒绝（fail-closed）。
5. **记忆即复利** —— Agent 学到的每个稳定事实都沉淀为文件，下次会话自动带上。
6. **实验必须可归因** —— Fork 固定模型、禁用 fallback、隔离工作区；一次实验只改变用户明确选择的变量。
7. **完成必须有证据** —— 模型文本只是候选结论；机器检查与所需 Review 通过后才进入可信完成终态。

## 边界（我们不做什么）

- 不做账号体系、多租户、云服务
- 不做向量检索式记忆、embedding 代码索引
- 不做固定角色多 Agent 协作（Architect/Coder/Reviewer 式分工）
- 不做 IDE 插件（CLI + Web 双入口已足够）
- MVP 不做历史文件时光机：Fork 的文件状态取创建实验时的当前项目快照
- MVP 不做通用 Agent Manifest、外部 Runtime Adapter 或语义级双栏回放；先用内置 Coding Agent 验证 Harness 契约
